# Требования к программному продукту

## 1. Общие сведения

- **Продукт:** «Система учета студентов».
- **Предметная область:** учет студентов колледжа, групп и специальностей.
- **Основа:** `passport.md`, `docs/domain.md`.
- **Цель документа:** зафиксировать проверяемые требования к первой версии продукта.

## 2. Роли пользователей

| Роль | Описание |
|---|---|
| `student` | Студент. Видит только свою карточку и может сменить свой пароль |
| `operator` | Оператор учебной части. Ведет студентов и группы, смотрит отчеты |
| `admin` | Администратор. Управляет пользователями, ролями, специальностями и аудитом |

## 6. Пользовательские сценарии

### S-01. Оператор добавляет нового студента

- **Актор:** оператор.
- **Цель:** создать карточку студента.
- **Предусловия:** оператор авторизован, группа существует.
- **Основной поток:**
  1. Оператор открывает раздел «Студенты».
  2. Нажимает «Добавить студента».
  3. Заполняет ФИО, дату рождения, email, телефон, группу и статус.
  4. Нажимает «Сохранить».
  5. Система проверяет данные и уникальность email и телефона.
  6. Система создает студента, запись истории и запись аудита.
  7. Система показывает карточку созданного студента.
- **Результат:** студент добавлен в систему.
- **Исключения:** пустые поля — 400; дубликат — 409; нет прав — 403; ошибка БД — 500.

### S-02. Студент просматривает свою карточку

- **Актор:** студент.
- **Цель:** увидеть свои данные.
- **Предусловия:** студент авторизован, его учетная запись связана с карточкой.
- **Основной поток:**
  1. Студент входит в систему.
  2. Открывает раздел «Моя карточка».
  3. Система определяет студента по токену.
  4. Система показывает только его данные.
- **Результат:** студент видит свою карточку.
- **Исключения:** попытка открыть чужой ID — 403; учетная запись не связана со студентом — 404.

### S-03. Оператор ищет студента

- **Актор:** оператор.
- **Цель:** быстро найти нужного студента.
- **Предусловия:** оператор авторизован.
- **Основной поток:**
  1. Оператор открывает список студентов.
  2. Вводит часть ФИО, email или телефон.
  3. Выбирает группу или статус.
  4. Система возвращает подходящие записи.
- **Результат:** оператор видит отфильтрованный список.
- **Исключения:** ничего не найдено — пустое состояние с пояснением.

### S-04. Оператор переводит студента в другую группу

- **Актор:** оператор.
- **Цель:** зафиксировать перевод студента.
- **Предусловия:** студент и новая группа существуют.
- **Основной поток:**
  1. Оператор открывает карточку студента.
  2. Нажимает «Перевести».
  3. Выбирает новую группу и дату перевода.
  4. Система закрывает текущую запись истории.
  5. Система создает новую запись истории.
  6. Система обновляет текущую группу студента.
  7. Система добавляет запись в аудит.
- **Результат:** студент находится в новой группе, история сохранена.
- **Исключения:** группа не найдена — 400; нет прав — 403.

### S-05. Администратор управляет пользователем и смотрит аудит

- **Актор:** администратор.
- **Цель:** создать пользователя и проверить действия в системе.
- **Предусловия:** администратор авторизован.
- **Основной поток:**
  1. Администратор открывает раздел «Пользователи».
  2. Создает пользователя и назначает роль.
  3. Открывает журнал аудита.
  4. Фильтрует записи по пользователю и дате.
- **Результат:** пользователь создан, действия видны в аудите.
- **Исключения:** логин уже занят — 409; слабый пароль — 400.

## 7. Критерии приемки

### AC-01. Аутентификация и роли

- **Дано:** в системе есть студент, оператор и администратор.
- **Когда:** каждый пользователь входит и пытается открыть защищенный раздел.
- **Тогда:** студент не получает доступ к чужим карточкам и админ-разделам, оператор не видит аудит и управление пользователями, администратор видит все разрешенные разделы.

### AC-02. Создание студента

- **Дано:** оператор авторизован.
- **Когда:** он отправляет корректные данные нового студента.
- **Тогда:** возвращается 201, студент появляется в списке, создаются запись истории и запись аудита.
- **Когда:** email уже существует.
- **Тогда:** возвращается 409, дубликат не создается.

### AC-03. Поиск и фильтрация

- **Дано:** в базе есть студенты разных групп и статусов.
- **Когда:** оператор вводит ФИО, email или телефон и выбирает фильтр.
- **Тогда:** в результате только подходящие записи, а при отсутствии совпадений показывается пустое состояние.

### AC-04. Перевод между группами

- **Дано:** студент состоит в группе A.
- **Когда:** оператор переводит его в группу B.
- **Тогда:** текущая группа меняется на B, запись в истории группы A закрывается, создается запись для группы B, действие попадает в аудит.

### AC-05. Отчеты

- **Дано:** в базе есть студенты и группы.
- **Когда:** оператор открывает отчет.
- **Тогда:** количество студентов по группам, специальностям и статусам совпадает с данными в БД.
