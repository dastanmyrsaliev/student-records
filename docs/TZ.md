## 2. Назначение и цели

### 2.1. Назначение

Веб-приложение предназначено для централизованного учета студентов колледжа, групп и специальностей, быстрого поиска информации и разграничения доступа по ролям.

### 2.2. Цели

- заменить ручное ведение разрозненных списков единой базой данных;
- сократить время поиска и изменения данных о студентах;
- сохранить историю переводов студентов между группами;
- обеспечить разграничение прав студента, оператора и администратора;
- сформировать отчеты по группам, специальностям и статусам.

## 3. Область применения

Система применяется в учебной части колледжа и используется локально или в локальной сети. Первая версия не предназначена для публичного интернет-развертывания и не заменяет официальные информационные системы учреждения.

## 9. Требования к данным

### 9.1. Состав базы данных

| Таблица | Назначение |
|---|---|
| `roles` | Роли пользователей |
| `users` | Учетные записи |
| `students` | Карточки студентов |
| `groups` | Учебные группы |
| `specialties` | Специальности |
| `student_group_history` | История нахождения студента в группах |
| `audit_log` | Журнал действий |

### 9.2. Основные связи

- `specialties` 1:N `groups`;
- `groups` 1:N `students` (текущая группа);
- `students` M:N `groups` через `student_group_history`;
- `roles` 1:N `users`;
- `students` 1:0..1 `users`;
- `users` 1:N `audit_log`.

### 9.3. Ограничения целостности

- email и телефон студента уникальны;
- группа должна существовать до зачисления студента;
- нельзя удалить группу, в которой есть студенты;
- запись истории содержит студента, группу и дату начала;
- журнал аудита не редактируется и не удаляется через приложение;
- пароль хранится только в виде хеша.

## 10. Требования к API

### 10.1. Формат

- REST, JSON;
- базовый префикс `/api`;
- защищенные маршруты требуют `Authorization: Bearer <token>`;
- ошибки возвращаются в JSON с полями `error` и `message`.

### 10.2. Минимальный набор endpoint

```text
POST   /api/auth/register
POST   /api/auth/login
GET    /api/auth/me

GET    /api/students
GET    /api/students/:id
POST   /api/students
PUT    /api/students/:id
DELETE /api/students/:id

GET    /api/groups
POST   /api/groups
PUT    /api/groups/:id
DELETE /api/groups/:id

GET    /api/specialties
GET    /api/reports/summary
GET    /api/audit
```

### 10.3. HTTP-коды

| Код | Значение |
|---|---|
| 200 | Успешный запрос |
| 201 | Создано |
| 204 | Успешно без тела ответа |
| 400 | Некорректные данные |
| 401 | Не авторизован |
| 403 | Доступ запрещен |
| 404 | Не найдено |
| 409 | Конфликт, например дубликат |
| 500 | Внутренняя ошибка сервера |

## 12. Требования к безопасности

- пароли хешируются bcrypt;
- JWT имеет срок действия;
- секреты хранятся в `.env`, `.env` исключен из Git;
- SQL-запросы параметризованы;
- пользовательский ввод валидируется на сервере;
- вывод данных защищен от XSS;
- проверка ролей выполняется на Backend;
- проверяется доступ к объекту по ID, чтобы исключить IDOR;
- ошибки не раскрывают SQL, Stack Trace, пути и секреты;
- используются helmet и rate limiting;
- для production предусматривается HTTPS.
